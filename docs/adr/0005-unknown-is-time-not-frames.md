# 「未知画面」是时间信号，不是帧计数

## 背景

`unknown_limit = 120` 是各场景的兜底闸门：累计有多少帧被判成 `unknown` 就收工。它的**语义**是「机器人迷路了（认不出自己在哪）」，但**实现**是「这一轮任务里画面分类成 unknown 的跳变次数」——一个随运行时长单调增长的量。三次同形事故：

- **2026-09-30 幻象**：`目标=999999 套`（无界），38 套时以「未知画面累计 121 次」收工。
- **2026-10-16 五重**：手操一局长战斗就能把计数推过 120，而越线那一帧正好是本场收场 → 「打完一场就死」。已按 #76 打了补丁：**战斗 episode 内的 unknown 不计**（`agent/wuchong_impl.py::counts_as_unknown`）。
- **2026-10-19 14:33 深渊**：12:45 起跑，19 战全部正常记账，1h48m 后在第 20 战结算转场帧上以「未知画面累计 121 次」收工。逐帧重建（`debug/maafw*.log` 的 `abyss_state` 结果行）：本轮 725 帧、110 段 unknown，占帧数 15.3%；**连续驻留中位 3s、p95 6s、最长 16s**，构成是「结算→下一战」53% +「战斗→结算」40% —— **没有一次是「迷路」**。

两条结构判断，本 ADR 就是为了把它们钉死：

1. **无界会话 + 累计量 = 必然越线。** 深渊「一直往下刷、不关心几套」，会话没有终点，任何累计计数器迟早越线（≈5.8 段/战，19 战烧完 120）。五重/幻象是**有界**任务（打够 N 次 / 刷 N 套），只是被目标截断才侥幸没死。
2. **「转场帧」与「迷路」的区别只在持续。** 正常转场 1~16 秒；迷路是持续的、没有任何已知页面命中。用「累计帧数」表达「持续」，量纲一开始就错了。

## 决定

1. **全仓删除「未知画面累计」**：`unknown_count` / `unknown_limit` 不再存在。三个持有者（`agent/battle_loop_core.py` 通用引擎 = 幻象、`agent/abyss_impl.py`、`agent/wuchong_impl.py`）收敛到**同一个原语** `LostClock`：进入 unknown 打点、命中任一已知页清点、`in_fight` 期间不打点（#76 的结论并入原语，不是删掉）。
2. **闸门改用连续秒数 `lost_sec`**：`连续 {n}s 认不出画面（最后已知页：{last}）`。阈值按场景**数据化**（`scene/*.py`，与 `ZERO_PROGRESS_SEC` 同处），不进 GUI 选项：
   - 深渊 **60s**（实测 p95 6s、最长 16s → 3.75× 余量）；
   - 五重 / 幻象先同值 60s —— **阈值欠账**：本机没有它们完整会话的逐帧样本（手操战斗不走 MAA 识别节点），上线后第一个会话用日志复核。
3. **收工原因区分两类闸门**：「认不出」（迷路）与「没进展」（零进度 / 无新关卡 / 总时长）。后者才是「关卡打不过？」的正确表达；今天 08:06 那次停错页被写成「打不过？」，就是两类混写的后果。
4. **恢复先只给深渊**：深渊是无界会话，值得「归位重导航 → 继续」（最多 2 次）。五重/幻象的迷路多发生在共斗房/房间流里，恢复要各自真机帧，**记为欠账**，不在本决定里。
5. **守卫**：全仓出现 `unknown_count` / `未知画面累计` 即红；`#76` 的 `wuchong-unknown-not-counted-in-fight` 改指 `LostClock.observe(..., in_fight=True)`，继续钉住「战斗内不打点」。

## 考虑过的选项

- **(a) 调大上限（240 / 480）**：把「19 战必死」变成「38 战必死」，无界会话仍然必死。只是把死亡推后，还多了一次「看起来调好了」的错觉。
- **(b) 每战清零**：能救深渊一圈，但量纲仍是帧噪声；且「这一战还没打完」与「我迷路了」被混成同一件事。
- **(c) 只把 #76 接进深渊**：实测剩余 66 段 / 19 战 → 30 战约 **104**，刚好压在 120 线下 —— 一圈能过，下一圈翻。这是最危险的选项：它会让「修好了」看起来成立。
- **(d) 时间口径（本决定）**：直接对「持续」这个语义建模，与既有的「没进展」闸门正交。

业界对照（本仓 `docs/research/pipeline-exception-patterns.md` §3）：MaaEnd 用 `SceneAnyEnterWorld` 万能跳转**恢复**，MAA 本体用 `maxTimes + exceededNext` **有界结束**，官方 sample 把 `[JumpBack]` 放在 `next` 末尾指向「预置条件」。**三家都不数「认不出的帧」** —— 有界性落在节点级 `timeout` / `max_hit` 或 C++ 层重试预算上。

## 后果

- **改三处代码 + 三处 override**：`battle_loop_core.py`、`abyss_impl.py`、`wuchong_impl.py`；`interface.json`（WuchongGiveUp / PhantomGiveUp）与 `agent/side_impl.py`（批次模式的 PhantomGiveUp override）。
- **`lords_unknown` 不动**：那是**页面态**（领主战页认不出），与 `unknown`（帧判定结果）同名不同物。删错了会让领主战的死线消失。
- **删掉计数器不会变成无界空转**：每个场景本来就有一条「没进展」闸门（深渊 300s 零进度 / 900s 无新关卡，五重 900s，幻象 900s），那才是它们真正的语义边界。计数器只是抢在它前面误杀。
- **用户可感知的行为变化**：深渊不再在第 19~20 战自杀；收工原因从「未知画面累计 121 次」变成「连续 60s 认不出画面（最后已知页：…）」。按 `docs/agents/release-policy.md` 进攒批，不单独发版。
- **欠账（诚实交代）**：五重/幻象的 `lost_sec` 未用本机样本标定；五重/幻象的恢复动作未做；深渊恢复的页面判据需要两张真机帧（五重决战页 / 深渊迷路页）才能定 —— 没帧之前不写判据。
