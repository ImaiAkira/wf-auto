# 手操时「自动」只在战斗页关；战斗内其余自动切换仍然禁止

## 背景

#56 二批曾裁决（运维 2026-10-15，记于 `scene/auto_switch.py` 顶部）：**「自动」的切换一律挪到战斗外**
（编队页/房间页），战斗内不再切自动；并把它写成守卫 `auto-outside-no-in-battle-switch` /
`auto-outside-page-scoped`（`tools/contract_hooks/hooks_auto_outside.py`）—— 其中一条明确要求
**战斗 HUD 的「自动」永不被认作开关**。

该裁决基于真机根因（编队页「自动」与战斗 HUD「自动」是两个控件、位置不同，全屏判据会互相误命中），
这一条**今天仍然成立**。但它对**手操**这一条路径的结论被运维推翻（spec `docs/spec/wuchong-spec.md`
A2/A5/B1、缺陷 D4）：

> 「自动的关闭**做在编队页不管用** —— 游戏会在战斗里又把它打开，所以**必须在战斗页关**。」
> 「1.手操：**只在战斗页关掉**。」

即：编队页把「自动」关掉之后，游戏进入战斗时会重新把「自动」打开 → 运维选「手操」却看到角色自己在动。
所以**手操**这条路径必须在**战斗页**再关一次。

## 决定

1. **手操（`是否手操=手操`）时，在战斗页把战斗 HUD 的「自动」关掉**，且**只做这一件事**：
   - **只关不开**：动作侧 `on` 恒为 `false`，`scene` 恒为 `wuchong`；
   - **只对五重**：其它场景一律不得出现在战斗页切自动的路径上（`scene.wuchong.MANUAL_ALLOWED_SCENES`）；
   - **一场战斗最多尝试一次**（会话闩锁；点后复查，仍为「开」只记失败、**不点第二次** —— 第二次点就是把它重新打开）；
   - **判不出就不动作**：定位不到 / 战斗页作用域不成立 / 状态读数不确定 → 不点，并打印**可见失败**；
   - **具名出口**：唯一允许破例的节点是 `WuchongBattleAutoOff`（白名单常量在守卫里具名登记）。
2. **战斗内其余自动切换继续禁止**：暂停菜单式切换（旧的 `WuchongBattleAutoGuard` / `pause_auto` /
   `open_pause` / `close_pause` / `battle_pause`）**一律保持删除**，不进暂停菜单、不点滑块。
   守卫的语义因此从「战斗内没有自动切换」**收窄**为「战斗内没有**暂停式**自动切换，
   且战斗页关自动只有这一个具名、只关不开、只对五重的出口」。
3. **两个同名控件永不互相认领**（ADR-0003「覆盖必须可报告」的落地）：
   - 编队页作用域（`is_team_auto_control`）**仍然拒绝**战斗 HUD 的「自动」；
   - 战斗页作用域（新增 `is_battle_auto_control`）**必须拒绝**编队页的「自动」。
   两条判据各自带守卫，互为反例。
4. **战斗页作用域的数据/机制放共享层**：控件判据与几何量放 `scene/auto_switch.py`（数据）+ 
   `agent/auto_switch_impl.py`（机制），**不放进 `scene/wuchong.py`** —— 战斗 HUD 的「自动」是每个模式的
   战斗都有的**全局控件**；放进五重会让下一个需要它的场景必然抄一份（ADR-0003 要消灭的正是这个）。
   五重只放**策略**（只有手操允许关、节点名、闩锁 key）。

## 考虑过的选项

- **(a) 维持二批裁决：只在编队页关** —— 运维真机已证伪（游戏会在战斗里把自动重新打开），本票验收第 1 条字面上不可能达成。
- **(b) 战斗内走暂停菜单切滑块（旧 `pause_auto` 那条路）** —— 需要主动暂停战斗（侵入式：暂停会打断连点节奏），
  且其几何量当年是**未校准的占位值**；只有真机证明「战斗页那个『自动』不可点/点了不切换」时才回退到这条路，
  并且要**再次裁决**（不是绕过守卫）。本决定不采用。
- **(c) 本决定。**

## 后果

- **守卫必须改**（`auto-outside-no-in-battle-switch` 收窄 + 新增互斥守卫），否则新出口与旧禁令互相打架 ——
  这是本 ADR 存在的理由：破例必须**具名、可报告、可检验**，绝不静默放宽。
- **必须真机取证的缺口（诚实交代）**：验收要求「真机帧 + 日志可证」，而战斗页「自动=**关**」的帧
  **仓库里一张都没有**（现有唯一真机帧 `tools/frames/auto_battle_hud_hit.png` 是「开」态，按钮青绿填充
  均值 RGB ≈ (93,191,183)）。因此本决定的**关态判据只按「开」帧 + 合成反例（把探针区涂灰须读成「关」）标定**，
  真机校准是**欠账**：必须补 `tools/frames/battle_auto_hud_on.png` / `battle_auto_hud_off.png` /
  `battle_auto_hud_reclick_on.png` 三帧（720 空间），并把它们钉进守卫（缺帧即红）。**帧一旦过期，关态判据即作废。**
- 误判的两种代价不对称，故纪律是「只认正证据」：**假 OFF**（明明是开却读不出来）→ 不点 → 运维仍看到「选了手操还是自动」
  （票面第 1 条不成立，但**可控**）；**假 ON**（明明是关却读成开）→ 点一下 → **把它打开**（正是运维抱怨的那件事）。
  后者更严重，所以：只认正证据 + 一场一次 + 点后复查不再点 + 判不出不动作。
- 战斗页的关自动**不改变**「手操连点」的行为：连点由 `agent/wuchong_impl.py` 的引擎负责，持续到
  **结算 / 关卡失败**才交还（#71 的另一半，见 `docs/spec/wuchong-spec.md` B1/D1）。
