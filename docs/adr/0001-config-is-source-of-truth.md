# 配置是真源，pipeline JSON 保留为可读产物

## 背景

MAA 实际加载的是 `assets/resource/pipeline/*.json`，而「场景级复用」要求新增一个领主战类成员时不必改 `agent/*.py`。于是必须回答一个问题：谁是真源？

## 决定

**Python 场景配置是唯一真源**；pipeline JSON **不被清空、也不被整体生成**，它保留人类可读的流程链。配置只负责两件事：

1. **校验** —— JSON 与配置不一致时，离线套件必须变红；
2. **注入** —— 把跨场景通用的异常组 / 事件挂载写进 JSON，且必须**幂等**（重跑不改字节）。

## 考虑过的选项

- **(a) JSON 手写，靠共享 `Pub*` 节点复用** —— 无法保证「新增场景不改代码」，这正是当前 39 个成员各占一个 GUI 选项的原因。
- **(b) 配置为真源，JSON 全部由配置生成** —— 真机看到的与代码里写的隔了一层。DSH 的 8 份审计反复栽在这条路上：生成物与源漂移、行尾被改坏、`--prove-red` 打错副本。
- **(c) 本决定。**

## 后果

- JSON 里**仍然存在手写的链**，所以「校验」这一步不是可选的：一旦少了它，本决定就退化成 (a)。
- 注入必须对同一份 JSON 可重复执行且结果字节不变，否则 `git status` 会永久假脏，并掩盖真实改动。
